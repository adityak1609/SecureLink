A five-minute demonstration

  1. Start your devices

    Use Start local demo. Show the three distinct process IDs in Your device channel.

  2. Send all three media types

    Use the text, image and audio samples. Transfer progress uses actual chunk acknowledgements.

  3. Receive and inspect

    Choose Receive on each file. SHA-256 checks the server copy before Preview or Save becomes available.

    Open Traffic analysis and export PCAP, SQLite and XML. Explain the difference between a stream observation and a network packet. Open Testing & results to run and export the isolated requirement checks.

Use two physical devices

Run the server and witness using the documented LAN setup. The GUI remains on the client computer; Connect a device authenticates to the remote server.

The GUI uses runtime/gui/credentials/client.json. Securely provision the matching device secret in the remote server registry, or replace the GUI client credential file with your provisioned client file while the application is closed. Also provision the GUI signing_public.json registry on the receiver and pass it with bank_server.py --signing-keys. Keep signing_private.json on the client. Never send credentials through the frontend.

PER-TRANSFER REVIEW EVIDENCE

Inspect the proof.

Logs, readable timestamps, measured operations, image fidelity, ciphertext, hashes and signatures.

Send a file, then select it to inspect its evidence.

Ciphertext is a bounded sample of an actual encrypted media record, with its nonce and GCM tag; it is not the whole encrypted file. Image MSE/PSNR describe original-versus-received pixel fidelity. Times are displayed in IST (UTC+05:30); logs and exports retain original UTC values. Timestamps are observed wall-clock times, not trusted timestamp certificates. Client activity logs are ordinary local records; server audit integrity is checked separately in Security & audit.

MEASURED CRYPTOGRAPHIC OPERATIONS

Every operation.
Measured.

Inspect actual AES-GCM, SHA-256 and Ed25519 calls for each file and direction.

Send a file, then select it to inspect its measured operations.

Times use the local high-resolution clock and are displayed in milliseconds. AES measurements include cryptographic library setup and calls, not socket waits. SHA-256 measurements include file reads. Client measurements include retries; receiver measurements cover the final server connection up to encoding its last response, so final acknowledgement encryption is excluded. Missing operations are shown as not performed, not as zero time. Clock units do not imply nanosecond accuracy.

Method and scope

Measurements describe this machine, input and configuration. AES speed uses plaintext bytes divided by encryption or decryption time. Ed25519 signs a fixed-size file digest manifest; key generation and file hashing are outside its measured signing and verification calls.
